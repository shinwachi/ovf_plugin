1. Get the right download

Find your KNIME version under Help › About KNIME, then download the installer for it. There are two builds, and the installer refuses the wrong one.

Your KNIMEInstaller (Windows, Linux)Update-site address (macOS, or KNIME's wizard)

No internet on the KNIME computer? Copy the zip over. It has everything inside. All files are on the downloads page.

2. Choose how to install

Setting up many computers? Install once, then copy the result to the others: see section 11.

All users is the better choice when people share one KNIME: there is one copy to look after, and it keeps working when an administrator changes KNIME. Just me needs no rights, but each person installs and updates their own copy, and it stops loading if an administrator later changes KNIME (section 8 has the fix).

If you have several KNIME versions

The installer offers two ways to choose, and changes only the KNIME you choose. Run it once for each KNIME that should have the plugin, using the matching zip.

  • Scan lists every KNIME it finds, with its version and whether it already has the plugin. Pick one by number. It looks in the usual places, so a KNIME somewhere unusual may not be listed.
  • File picker lets you select knime.exe (Windows) or knime (Linux) yourself. On Linux it needs a desktop, and zenity or kdialog. If no picker can open, for example over SSH, you can type the folder instead.

3. Windows

All users You need administrator rights

  1. Close KNIME, and ask anyone else using it to close it too. If someone can't, you can still install: see section 10.
  2. Extract the zip. Right-click it › Extract All... Running from inside the zip doesn't work.
  3. In the extracted folder, right-click install-ovf.cmd › Run as administrator.
  4. Choose your KNIME: type 1 to scan and pick from a list, or 2 for a file picker. Then type 1 for who gets it.
  5. Restart KNIME. Do this for everyone using it.

Then set the recommended folder permissions, so ordinary users can't change KNIME by accident. In an administrator Command Prompt, from the extracted folder:

install-ovf.cmd -Knime "C:\Program Files\KNIME" -Mode admin -ApplyPermissions

Just me No special rights needed

  1. Close KNIME.
  2. Extract the zip. Right-click it › Extract All...
  3. In the extracted folder, double-click install-ovf.cmd.
  4. Choose your KNIME: type 1 to scan and pick from a list, or 2 for a file picker. Then type 2 for who gets it.
  5. Restart KNIME.

The KNIME folder is the one holding knime.exe. To find it, right-click the KNIME shortcut › Open file location.

If Windows warns about a downloaded file, choose More info › Run anyway. If your organization's policy blocks the script, ask your administrator: they need to allow or sign install-ovf.ps1.

4. Linux

All users You need sudo

  1. Close KNIME, and ask anyone else using it to close it too. If someone can't, you can still install: see section 10.
  2. Extract the zip into a new folder, then go there.
  3. Run sudo ./install-ovf.sh
  4. Choose your KNIME: type 1 to scan and pick from a list, or 2 for a file picker. Then type 1 for who gets it.
  5. Restart KNIME. Do this for everyone using it.
unzip ovf-serverconnector-5.x-1.0.9-installer.zip -d ovf-installer
cd ovf-installer
sudo ./install-ovf.sh --knime /opt/knime --mode admin --apply-permissions

This one command also sets the recommended folder permissions. Change 5.x to 4.1.x and /opt/knime to your KNIME folder as needed.

Just me No special rights needed

  1. Close KNIME.
  2. Extract the zip into a new folder, then go there.
  3. Run ./install-ovf.sh without sudo.
  4. Choose your KNIME: type 1 to scan and pick from a list, or 2 for a file picker. Then type 2 for who gets it.
  5. Restart KNIME.

The KNIME folder is the one holding the knime program, knime.ini and plugins.

5. macOS

Not tested on macOS. The plugin has no Windows- or Linux-specific code, so it's expected to work, but nobody has confirmed it. The installer scripts don't support macOS, so use KNIME's own wizard.
  1. Open the wizard: File › Install KNIME Extensions... In KNIME 5's Modern UI: Menu › Install extensions.
  2. Click Add..., then paste the update-site address from section 1 into Location. Click Add.
  3. Tick OVF Server Explorer, click Next, accept the license, click Finish.
  4. KNIME warns that the plugin is unsigned. Choose Install anyway.
  5. Restart KNIME when asked.

The wizard also works on Windows and Linux, but it can't ask who the plugin is for. It installs for everyone if you can write to the KNIME folder, and otherwise for you alone.

6. Check that it worked

KNIME 5: the tab is only in the classic user interface. If KNIME opens in the Modern UI (a dark bar with Home, Preferences and Menu at the top), click Menu › Switch to classic user interface. KNIME reopens with the tab. To go back, click Open KNIME Modern UI at the top right.

7. Where the files go, and permissions

WhatWhereWho should have access
KNIME folderC:\Program Files\KNIME
/opt/knime		Administrators: full control. Everyone else: read and execute only, on all files inside.
Private area, one per personC:\Users\you\.eclipse\<id>
~/.eclipse/<id>		Only that person. KNIME creates it. Don't change or share it.
Workspace, one per personC:\Users\you\knime-workspace
~/knime-workspace		Only that person. Two people can't have one workspace open at once.

Workspaces need nothing

The installer never asks for a workspace and never changes one, so an administrator can install for all users without touching anyone's. The first time a workspace opens in a KNIME with the plugin, the plugin adds its own tab, including in workspaces that already have a saved layout.

  • Your server list is saved in the workspace. A new workspace starts with no servers, so add them again there.
  • A KNIME without the plugin can still open the workspace. It shows a red Server Explorer (needs OVF plugin) tab. Nothing is lost: the tab works again next time you use a KNIME with the plugin.

Check a KNIME

To see this report for your own computer without changing anything:

install-ovf.cmd -Knime "C:\Program Files\KNIME" -Check
./install-ovf.sh --knime /opt/knime --check

Two permission settings cause most problems:

  • Users can create files but not change them. This is the Windows default if KNIME is unzipped into a folder under C:\ instead of Program Files. Installs fail, nodes go missing, and the second person's KNIME may not start.
  • Everyone has full control. One user can uninstall the plugin for everybody.

An administrator can fix both with the permissions option:

install-ovf.cmd -Knime "C:\KNIME" -Mode admin -ApplyPermissions
sudo ./install-ovf.sh --knime /opt/knime --mode admin --apply-permissions

9. Install a new version, or remove

New versions appear on the home page and the downloads page. Nothing inside KNIME tells you about them.

Which version do I have?

  • File › Preferences › Server Connector names the plugin file, for example org.ovf.serverconnector_1.0.9.jar. The version is the number at the end.
  • The installer's scan shows it next to each KNIME, for example installed for everyone (1.0.6).

Update

Update the same way you installed. You don't need to remove the old version first, and you can skip versions: updates from 1.0.3, 1.0.4, 1.0.5 and 1.0.6 were tested. Server lists and settings are kept, because they're stored in each workspace.

You installed withTo update
The installer, All usersAn administrator runs the new installer, as in the steps below. Everyone gets the new version when they restart KNIME.
The installer, Just meEach person runs the new installer for themselves, as in the steps below.
KNIME's wizardRun the wizard again (section 5) with the same address and tick OVF Server Explorer. This route hasn't been tested. If KNIME won't install it, remove the old version first (below), then install.
A dropinClose KNIME, delete dropins/serverconnector and unzip the new dropin zip (section 11).
A copied KNIME folderUpdate the master copy, then copy it out again (section 11).

With the installer:

  1. Download the new installer zip for your KNIME (section 1).
  2. Close KNIME. For All users, ask everyone else to close it too, or see section 10.
  3. Extract it into a new folder. Don't extract over the old installer.
  4. Run it as you did the first time, and make the same choice for who gets it.
  5. Restart KNIME and check the version on the Server Connector page.

The installer prints Replacing the installed version... Before that you may see Cannot complete the install because of a conflicting dependency. Both are normal. The previous version's jar stays in plugins, unused, until the next update removes it.

install-ovf.cmd -Knime "C:\Program Files\KNIME" -Mode admin -ApplyPermissions
sudo ./install-ovf.sh --knime /opt/knime --mode admin --apply-permissions
If you installed Just me and an administrator then installs for all users, your own old copy keeps loading. Run the installer as Just me once to bring it up to date.

Remove

Close KNIME, then use the same mode you installed with. For an all-users change, ask everyone else to close it too (section 10).

install-ovf.cmd -Knime "C:\Program Files\KNIME" -Mode admin -Uninstall    (or -Mode user)
./install-ovf.sh --knime /opt/knime --mode admin --uninstall              (or --mode user)

If you used the wizard: Help › About KNIME › Installation Details, select OVF Server Explorer, click Uninstall...

If a tab then shows an error, close it. Your workflows aren't affected.

10. If people still have KNIME open

This is about All users installs, updates and removals. Asking everyone to close KNIME first is the safest way, but it isn't required. You can install anyway and ask people to restart. The installer lets you do this.

Why the steps ask people to close KNIME

KNIME reads its list of plugins only when it starts. A KNIME that is already open doesn't notice an install. It keeps using the version it started with, and the jar file for that version, until it restarts. Closing KNIME first avoids the problems in the table below, and makes sure everyone is on the new version straight away.

What happens if someone doesn't close it

While KNIME is open, you...What that person seesWhat to do
Install for the first timeKNIME carries on, without the tab.Restart. The tab appears.
Update to a new versionKNIME carries on with the old version, and the plugin keeps working. The old jar stays on disk.Restart to get the new version.
Change it again before they restart: a second update, a reinstall, or a removalThis change can delete the old jar they're still using. The tab may look normal, but a part of the plugin they haven't used yet can fail. For example, the server settings page shows Unable to create the selected preference page. KNIME itself stays open.Restart. This clears the error. To avoid it, get everyone restarted before you change anything again.
Remove the pluginKNIME carries on. After a restart, the tab shows Could not create the view.Close that tab.
Someone starts KNIME during the install, which takes a few secondsIn the one try made, KNIME started normally, without the new version.Restart.

No KNIME closed or lost its window in any of these tests. Save your work and restart if you see an error in the plugin. What the tests didn't cover is a workflow running, or one opened from a server with unsaved changes, at the moment the jar is deleted.

Install anyway and ask people to restart

  1. Run the installer as usual. If KNIME is running, it says KNIME appears to be running and asks Continue anyway?
  2. Type y. Typing anything else stops and changes nothing. With --yes or -Yes, it continues without asking.
  3. Ask everyone to save their work and restart KNIME. You have to tell them yourself: nothing inside KNIME says a new version is waiting.
  4. Check who still has it open (commands below), and wait for them before you change anything again.
Windows, in an administrator PowerShell:
  Get-Process knime -IncludeUserName | Select-Object UserName, Id

Linux:
  ps -eo user,args | grep '[/]plugins/org.knime.binary.jre' | cut -c1-70
The installer's warning only covers this computer. It can't see KNIME running on other computers from a shared network folder. On Windows it also reacts to KNIME running from any folder, not just the one you chose.

11. Transplant instead of installing

A transplant moves a working plugin to another KNIME by copying files, without running the installer there. It's the recommended way to give the plugin to many computers: install once on one master copy, test it, then copy that result everywhere. Every computer then gets exactly what you tested.

Your situationUse
A new computer, or a set of computers that should all be the sameWhole folder
Rolling out an update after the first installWhole folder, replacing the old one
Computers that already have a KNIME with their own extensions, which you want to keepDropin, or the installer
One computer, or a Just me installThe installer

Routine 1: whole folder

The plugin lives inside the KNIME folder when it's installed for All users, so it travels with the copy, and it works at any path. KNIME and every extension in the folder go with it.

  1. Make the master. Install for All users on one KNIME. Add any other extensions you want everyone to have.
  2. Close KNIME on the master and on the target. Replacing a folder under an open KNIME made the plugin's settings page fail in that session.
  3. Copy the whole KNIME folder. Use the same operating system on both: the folder includes a Java runtime built for that system.
  4. Set the permissions on the target (below).
  5. Open KNIME. The tab is there, including for people who have never used KNIME.
Windows, from an administrator PowerShell:
  robocopy "C:\Program Files\KNIME" "\\OTHERPC\C$\Program Files\KNIME" /E /COPY:DAT
  install-ovf.cmd -Knime "C:\Program Files\KNIME" -Mode admin -ApplyPermissions    (on the target)

Linux:
  tar czf knime.tgz -C /opt knime                  (or: zip -qry knime.zip knime)
  sudo tar xzf knime.tgz -C /opt                   (on the target)
  sudo ./install-ovf.sh --knime /opt/knime --mode admin --apply-permissions
Windows permissions depend on where you put the copy. Under Program Files, it gets the right access by itself and the permissions command is optional. Directly under C:\, ordinary users can create files but not change them, and the installer says so. The permissions command fixes that. It also installs the plugin from its zip, so use the zip for the same version as the master.

To update: update the master, close KNIME on the target, move the old folder aside, and copy the new one to the same path. People get the new version the next time they open KNIME, and their workspaces and server lists stay as they were. Anything added to the old folder on that computer alone is replaced, including other extensions. Keep the old folder until you've checked the new one.

Routine 2: dropin

Use this when the target's KNIME has to stay. It adds one folder, and it works on a read-only KNIME. Use the plain zip from the downloads page, the one that doesn't end in -installer or -updatesite, and match your KNIME: 5.x or 4.1.x.

  1. Close KNIME.
  2. Unzip into dropins in the KNIME folder, creating that folder if needed, so that you have dropins/serverconnector/plugins/org.ovf.serverconnector_<ver>.jar
  3. Open KNIME. The tab appears for everyone.
  • To update: close KNIME, delete dropins/serverconnector, and unzip the new version.
  • To remove: close KNIME and delete dropins/serverconnector. A workspace that used the plugin then shows the red tab, which you can close.
  • Use the right zip. The 5.x zip on KNIME 4.1.3 gave no tab and no message.
  • Don't also run the installer on it. After doing both, the installer's uninstall reported The plugin is still installed and left it there.
  • The plugin doesn't appear in Installation Details, and KNIME's uninstall can't remove it.

If the plugin was installed Just me

That copy lives in the person's home folder, so it stays behind when the KNIME folder is copied. Run the installer on the new copy.

What was copiedResult
KNIME folder onlyNo plugin. A new workspace shows no tab. A workspace that used it shows the red tab, and KNIME may offer an import wizard.
KNIME folder and the private area (.eclipse), same KNIME path, same user and home folderThe plugin works (tested on Linux only).
KNIME folder and the private area, different KNIME pathNo plugin: the private area's name depends on the KNIME path, so KNIME looks in a new one. You get the red tab, and KNIME may offer an import wizard (seen on 5.8.1).

What doesn't come with the folder

Workspaces are separate, so server lists stay on the first computer unless you copy them too. To bring a list, copy the workspace folder with KNIME closed. On Linux, the server list was still there afterwards, at the same and at a different KNIME path. Otherwise, add the servers again.

Don't copy only the changed files

Section 13 lists what an install changes, so it's tempting to copy just those files. Two ways of doing that were tested, and neither is recommended. Both show the tab at first.

13. Exactly what changes on disk

This section is for administrators and anyone curious. It lists what the plugin adds, how KNIME learns about it, and where its settings are kept. <ver> is the version, such as 1.0.9 or 1.0.9.413. Paths use /, and on Windows the same paths apply with \.

How KNIME finds the plugin

The program is one file, a jar. KNIME doesn't scan for new jars: at startup it loads the plugins named in a list called bundles.info. Adding one line to that list is what registers the plugin. The jar then tells KNIME about the Server Explorer view, the settings pages and a startup step that adds the tab.

All users Inside the KNIME folder

File, under the KNIME folderWhat changes
plugins/org.ovf.serverconnector_<ver>.jarThe program. New file.
features/org.ovf.serverconnector.feature_<ver>/feature.xmlNew file. Names the plugin as an installable item.
configuration/org.eclipse.equinox.simpleconfigurator/bundles.infoThe registration. One line added, shown below.
artifacts.xmlTwo records added: the jar and the feature. Its timestamp and count change too.
p2/org.eclipse.equinox.p2.engine/profileRegistry/KNIMEProfile.profile/New *.profile.gz files: KNIME's installer's record of what is installed. This is why the plugin appears in Installation Details.
configuration/config.iniOnly the date in its comment line changes.
Other files in configuration/ and p2/KNIME's own caches and logs, refreshed because its installer ran. These hold no plugin settings you need to manage.

The line added to bundles.info. The path is relative to the KNIME folder:

org.ovf.serverconnector,1.0.9,plugins/org.ovf.serverconnector_1.0.9.jar,4,false

The last two values are the plugin's start level and whether KNIME starts it straight away. Don't edit this file by hand. Use the installer, so that it stays in step with KNIME's installer records.

Nothing in the KNIME folder changes. Everything goes in your private area, one folder per KNIME:

Windows:  C:\Users\you\.eclipse\<id>\
Linux:    ~/.eclipse/<id>/

<id> looks like one of these, and the number comes from the KNIME folder's path:
  1877637008_linux_gtk_x86_64                                 (KNIME 4)
  org.eclipse.platform_4.31.0_1878567254_linux_gtk_x86_64     (KNIME 5)

Because this is a private copy of the list, it can go out of date. If an administrator changes KNIME, KNIME goes back to the shared list, which doesn't name your copy of the plugin. That is why a Just me install stops loading (section 8).

Settings: mostly in the workspace

The installer doesn't write any settings. The plugin writes them when KNIME runs:

<workspace>/.metadata/.plugins/org.eclipse.core.runtime/.settings/org.ovf.serverconnector.prefsYour server list, the active server, your choices about hiding prompts, and serverconnector.viewClosedAtExit=true if the tab was closed when KNIME last exited normally.
<workspace>/.metadata/.plugins/org.eclipse.e4.workbench/workbench.xmiKNIME's saved window layout, which now includes the tab. This is how a KNIME without the plugin knows to show the red tab.
<private area>/configuration/.settings/org.ovf.serverconnector.prefsJust me only: remembers that you've seen the one-time notice about a private install.

The workspace file after adding one server:

eclipse.preferences.version=1
serverconnector.activeServer=Test server
serverconnector.servers=[{"name"\:"Test server","url"\:"https\://server.example.com\:8443","allowSelfSigned"\:false,"type"\:"REMOTE"}]

It holds a name, an address and two options for each server. The plugin has no password or login setting, so none is saved.

What doesn't change

  • knime.ini, other extensions' files, and other KNIME folders.
  • Any workspace, during the install. The settings above appear later, when KNIME opens that workspace.
  • The Windows registry and environment variables: the installer has no code that touches them.

The permissions option is the one exception to "files only": --apply-permissions or -ApplyPermissions also changes who can access the files in the KNIME folder (section 7).

What removing it leaves behind

RemovedLeft in place
The bundles.info line, so KNIME stops loading the plugin, and the features/ folder.The current version's jar in plugins/, unused until the plugin is installed again or KNIME's installer clears it. One record in artifacts.xml. Older versions' jars until the next change (section 10).
Your workspace settings, including your server list, and the saved tab. If you install again, they come back as they were.

To remove every trace of a server list, delete org.ovf.serverconnector.prefs with KNIME closed.

These lists come from comparing every file before and after, on Linux with KNIME 4.1.3 and 5.8.1. On Windows, the jar, feature folder, bundles.info line and workspace settings file were confirmed at the same paths, but there was no full before-and-after comparison.
